# THI-116 — Robust terminal input: buffer-paste delivery, image paste, custom key handlers

**Linear:** [THI-116](https://linear.app/thibault-dody/issue/THI-116/robust-terminal-input-buffer-paste-delivery-image-paste-custom-key)
**Date:** 2026-05-14
**Status:** Design approved

## Summary

Extract three terminal-input features from the `periscope` project
(`~/github/periscope`) into Switchboard:

1. **Robust keystroke delivery** — replace `tmux send-keys -l` with a
   `load-buffer` + `paste-buffer` pipeline so literal text never touches tmux's
   argv parser. Fixes the parser silently dropping a standalone `;` keystroke
   and stripping embedded newlines.
2. **Image paste** — paste a clipboard image into a Claude Code agent pane; the
   backend writes it to a temp file and bracket-pastes the `@path` reference.
3. **Custom key handlers** — Cmd-combo line-editing shortcuts in the terminal
   modal, plus a single-Esc-to-pane / double-Esc-to-close model.

The three sub-features are independent but share one new backend primitive,
`tmux.deliver_text`.

## Background

Switchboard already injects keystrokes via `tmux send-keys -l`
(`backend/src/switchboard/services/tmux.py` → `send_keys`), used by both the
`/ws/pane` keystroke path (`ws.py`) and the `/api/send` command-palette path
(`actions.py`). tmux's command parser treats a standalone `;` argument as a
command separator, so a single `;` keystroke forwarded by xterm.js as one WS
message is silently dropped; embedded newlines are likewise stripped. Periscope
solves this with `load-buffer` (text on stdin) + `paste-buffer`.

## Non-goals

- WebSocket auto-reconnect — sibling ticket THI-117.
- Bracketed-paste detection on the `/ws/pane` keystroke path. xterm.js owns
  bracketed paste for that direction; the WS path stays a transparent
  passthrough.
- Image paste on non-agent panes. The `@path` attach syntax is Claude
  Code-specific and meaningless in a plain shell.
- Surfacing image-paste or key-handler affordances on window cards. Scoped to
  the terminal modal.

## Backend

### Shared primitive: `tmux.deliver_text`

```python
def deliver_text(session: str, index: int, text: str, *, bracketed: bool) -> bool
```

- Resolves `target = f"{session}:{index}"` and confirms the pane exists.
- `subprocess.run(["tmux", "load-buffer", "-b", buf, "-"], input=text,
  text=True, timeout=5)` — `buf = f"sb-in-{uuid4().hex[:8]}"`. Text enters on
  **stdin**, so tmux's argv parser never sees it.
- `subprocess.run(["tmux", "paste-buffer", "-d", "-b", buf, "-t", target,
  *(["-p"] if bracketed else [])], timeout=5)`. `-d` deletes the buffer after
  pasting; `-p` enables bracketed paste so a pasted block's embedded newlines do
  not each submit.
- Returns `bool` (False on missing pane or `subprocess` failure).

Uses `subprocess.run` directly rather than libtmux's `Server.cmd`, which cannot
pipe stdin. The module already drops to `pane.cmd` / direct calls where libtmux
cannot express something (see `capture_pane`).

Ref: periscope `server.py` `deliver_input()` (~L544).

### Refactor `tmux.send_keys`

New signature:

```python
def send_keys(
    session: str,
    index: int,
    *,
    keys: list[str] | None = None,
    paste: str | None = None,
    bracketed: bool = False,
) -> bool
```

- The `paste` branch delegates to `deliver_text(session, index, paste,
  bracketed=bracketed)`.
- When **both** `paste` and `keys` are supplied, `time.sleep(0.10)` between the
  paste and the keys — the periscope grace delay, so a TUI applies the pasted
  block before a trailing `Enter` lands.
- `keys` continue to go through `srv.cmd("send-keys", "-t", target, key)` per
  key. Key names (`Enter`, `C-c`, `Up`, …) are not literal text and do not hit
  the parser bug.
- `send_signal` is unchanged.

### Callers

- `ws.py` — `tmux.send_keys(session, index, paste=msg)` is **unchanged**;
  `bracketed` defaults to `False`. WS keystrokes remain a transparent
  passthrough — each keystroke acts immediately — mirroring periscope's
  `deliver_input`.
- `actions.py` `/api/send` — passes `bracketed=True`. The command palette's
  `paste` is always a typed block, so bracketing keeps embedded newlines from
  each submitting; the trailing `keys=["Enter"]` (after the 100 ms grace)
  submits once. No change to the `SendBody` schema.

### `tmux.pane_kind`

```python
def pane_kind(session: str, index: int) -> Kind | None
```

A small lookup helper mirroring `get_pane`, returning `_infer_kind(cmd,
window_name)` for the window's active pane, or `None` when it cannot be found.
Used to gate image paste to agent panes.

> **Coordination:** THI-104's implementation plan also introduces
> `tmux.pane_kind` with the same signature and intent. Whichever ticket lands
> second drops its copy. The two definitions are identical, so a merge conflict
> is trivial.

### Image paste endpoint

`POST /api/paste-image?session=&index=` in `actions.py`:

- Request body is the raw image bytes. `Content-Type` must be one of
  `image/png`, `image/jpeg`, `image/gif`, `image/webp` → otherwise **415**.
- Body size over `settings.paste_image_max_bytes` → **413**.
- Pane not found → **404**; `pane_kind(...) != "agent"` → **409** (image paste
  is agent-only).
- Sweep stale files — prefix `switchboard-paste-`, mtime older than 1 hour —
  from `tempfile.gettempdir()`, then write the bytes to
  `<tmpdir>/switchboard-paste-<uuid>.<ext>` (`ext` from the content type).
- `deliver_text(session, index, f"@{path} ", bracketed=True)` — Claude Code's
  file-attach syntax, with the trailing space periscope uses.
- Returns `{"ok": true, "path": str, "bytes": int}`.
- CSRF: a `POST`, so `SecurityMiddleware`'s double-submit check applies
  unchanged.

Ref: periscope `server.py` `/api/paste-image` (~L1137), `_sweep_old_paste_images`
(~L1127).

### Config

Add to `Settings` (`config.py`):

```python
paste_image_max_bytes: int = 10 * 1024 * 1024  # 10 MiB
```

Overridable via `SWITCHBOARD_PASTE_IMAGE_MAX_BYTES`.

## Frontend

### `client.ts`

New helper:

```ts
export async function pasteImage(
  session: string,
  index: number,
  blob: Blob,
): Promise<boolean>
```

`fetch` POST to `/api/paste-image?session=&index=` with `content-type:
blob.type`, `...csrfHeaders()`, and `body: blob`. Resolves `r.ok`.

### `lib/termKeys.ts` (new)

A pure, unit-testable module holding the key-handling logic so it can be tested
without rendering xterm (precedent: `cardNav`, `filter`, `urlState`):

- `escAction(now: number, lastEsc: number): "send" | "close"` — the double-Esc
  state machine. Returns `"close"` when `now - lastEsc <= 400`, else `"send"`.
- `comboBytes(e: KeyboardEvent): string | null` — maps a Cmd-combo to the
  control bytes to forward, or `null` when the event is not a handled combo:

  | Combo | Bytes |
  |-------|-------|
  | ⌘⌫ | `\x15` (Ctrl-U — kill line backward) |
  | ⌘⌦ | `\x0b` (Ctrl-K — kill line forward) |
  | ⌘← | `\x01` (Ctrl-A — line start) |
  | ⌘→ | `\x05` (Ctrl-E — line end) |

  ⌘⌫ maps to a single Ctrl-U rather than periscope's 200-backspaces hack.

### `TerminalModal.tsx`

**Esc handling.** The existing `document`-level keydown effect currently does
`if (e.key === "Escape") onClose()`. Replace that branch with the double-Esc
state machine: keep a `lastEscRef` timestamp; `escAction(...)` returns `"send"`
→ forward `\x1b` over the WS, or `"close"` → `onClose()`. The ⌘=/⌘-/⌘0 zoom
branch is untouched. In **snapshot** (read-only) mode there is no pane to
forward to — Esc stays a single-press close.

**Cmd-combo line editing.** In the same keydown handler, `comboBytes(e)` →
when non-null, `preventDefault()` (⌘←/⌘→ are bound to browser history nav) and
forward the bytes over the WS. Combos are no-ops in snapshot mode.

**Image paste.** Add a capture-phase `paste` listener on the terminal host
element. If `e.clipboardData` carries an image item **and** `win.kind ===
"agent"`: `preventDefault()`, read the blob, call `pasteImage(...)`. On success
the pane shows the `@path` (the server pasted it). If the pane is not an agent
pane, or the upload returns 413/415/409, surface a transient message via the
existing `ToastStack`; a non-image paste falls through to xterm normally.

The WS socket is currently scoped to the construction effect (`sock`), but the
keydown handler lives in a separate effect and cannot see it. This ticket
introduces a `wsRef` (a `useRef<WebSocket | null>`) set alongside `ws` in the
construction effect and cleared on teardown; the keydown handler and the paste
listener forward through `wsRef.current`. (THI-104's plan introduces the same
`wsRef` independently — see the coordination note above.)

## Edge cases & error handling

1. **`;` and newlines.** The regression the ticket exists for: a literal `;` or
   embedded `\n` in `paste` now round-trips because the text travels on stdin,
   never as a tmux argv element. Covered by a `test_tmux.py` round-trip test.
2. **Control bytes over the WS.** xterm.js `onData` already emits raw control
   bytes (`\x03` for Ctrl-C, `\r` for Enter). `deliver_text` with plain
   `paste-buffer` (no `-p`) writes them verbatim, so they act immediately —
   same as periscope's `deliver_input`.
3. **`subprocess` failure / missing tmux.** `deliver_text` catches and returns
   `False`; `send_keys` and `/api/send` propagate that as the existing 404 /
   `{"ok": false}` paths do.
4. **Oversize or non-image upload.** Rejected at the endpoint with 413 / 415
   before any file is written.
5. **Temp-file growth.** Each `/api/paste-image` call sweeps stale
   `switchboard-paste-*` files (mtime > 1 h) before writing, bounding disk use
   without a background task.
6. **Double-Esc race.** A second Esc just outside the 400 ms window forwards a
   second `\x1b` to the pane rather than closing — harmless; the user presses
   Esc again.
7. **Snapshot mode.** No WS socket: Esc is a single-press close and the
   Cmd-combos / image paste are inert (nothing to send to).

## THI-104 coordination

THI-104's spec states "Esc stays 'close modal'." This ticket changes that:
single Esc → pane, double-Esc → close. THI-104's `PromptOverlay` owns Esc only
while it is focused (its `onKeyDown` already lets Escape fall through); when no
overlay is mounted, the modal's handler applies the double-Esc model. **Action:
update `docs/superpowers/specs/2026-05-14-thi-104-design.md` and its plan** to

## Testing

### Backend (`pytest`)

- `test_tmux.py` —
  - `deliver_text` builds the expected `load-buffer` / `paste-buffer` argv
    (mock `subprocess.run`); `bracketed=True` adds `-p`, `bracketed=False` omits
    it.
  - `send_keys` with both `paste` and `keys` sleeps between them.
  - Round-trip: `send_keys(paste="a;b\nc")` passes `"a;b\nc"` through as the
    `load-buffer` stdin payload unmodified — the `;` / newline regression.
  - `pane_kind` returns `"agent"` / `"shell"` / `None` for the matching lookups.
- `test_actions.py` — `/api/paste-image`: 415 on a non-image content type, 413
  over the size cap, 409 on a non-agent pane, 404 on a missing pane, happy path
  writes a temp file and returns `{"ok": true}`. A CSRF-less POST still 403s
  (existing middleware-test pattern).

### Frontend (`vitest`)

- `lib/termKeys.test.ts` (new) — `escAction` returns `"send"` then `"close"`
  across the 400 ms boundary; `comboBytes` maps each ⌘-combo to the right bytes
  and returns `null` for unrelated events.
- `client.test.ts` — `pasteImage` sets `content-type` from the blob and
  includes the CSRF header (extend existing client tests, or add the file if
  none exists).
- Component / image-paste behavior in `TerminalModal`: lib coverage plus manual
  verification. The frontend harness is lib-only today (per THI-104's notes); no
  new component-render harness is scaffolded here.

### Manual verification

- Type a command containing `;` and a multi-line block via the command palette,
  and via direct xterm typing — both arrive intact.
- Paste a screenshot into a Claude Code pane → the `@path` reference appears.
- Paste an image into a shell pane → ignored with a toast.
- Exercise ⌘⌫, ⌘⌦, ⌘←, ⌘→ at a shell prompt; confirm single Esc reaches the
  pane and double-Esc closes the modal.

## Risks

- **Bracketed paste support.** `paste-buffer -p` assumes the target app honors
  bracketed paste (Claude Code and readline-based shells do). An app that does
  not will see the literal `\e[200~` / `\e[201~` wrappers. Accepted: the
  `/api/send` path targets interactive panes, and this matches periscope's
  shipped behavior.
- **`@path` attach syntax.** Image paste assumes Claude Code's `@path`
  convention. If that convention changes, the one-line `f"@{path} "` string is
  the single point to update.
