# THI-136 — Documentation tab

**Linear:** [THI-136](https://linear.app/thibault-dody/issue/THI-136/add-full-documentation)
**Date:** 2026-05-25
**Status:** Draft

## Summary

Add an in-app **Documentation** modal that explains the visual vocabulary
of Switchboard via three annotated SVG diagrams:

1. **Session header / column header** — what each affordance does
   (drag handle, +claude / +shell, auto-rename ✨, rename, etc).
2. **Agent tile** — the chips, status pill, recap, pending box, footer
   actions, and the new context-% accent (THI-131/133).
3. **Shell / SSH tile** — the simpler card, focused on branch chip,
   preview, cpu/mem, footer actions.

The modal is entered from a new "Docs" button in the Header next to
Shortcuts / Settings, and from the final step of the first-run tour
(THI-96 — "More in Docs"). Content is static SVG with text callouts; no
markdown rendering, no live data, no external fetch.

## Background

Switchboard's UI has accumulated dense affordances over THI-87 / 88 / 96 /
115 / 67 / 110 / and the in-flight THI-128 / 129 / 130 / 131. New users —
and the maintainer, after a month away — have no canonical reference for
what each glyph means. The first-run tour (THI-96) introduces the
**four** big concepts; this Docs tab is the **encyclopedia** the user
returns to.

Existing modal patterns to follow:

* `SettingsModal.tsx` — large sectioned modal with a tabbed layout.
* `ShortcutsSheet` (THI-69) — modal triggered by `?` key, lives in
  Header.
* `StatusLegend` popover (THI-96) — small inline anchored popover; not a
  great fit here (too small).

Decision: a full-screen modal modeled on `SettingsModal`, not a popover.
The diagrams need room.

## Non-goals

* **Markdown / rich text.** Diagrams + short labels only. If a markdown
  knowledge base ever appears, it lives in `docs/` on disk and is
  cross-linked from this modal.
* **Dynamic content.** Each diagram is a static SVG asset bundled with
  the frontend. No live data, no per-user customization.
* **Tutorial replay.** The first-run tour (THI-96) plays once and links
  here; this modal is reference, not retraining.
* **Search.** Three diagrams; search would be noise.
* **External links.** Self-contained.

## Architecture

### Trigger surfaces

* **Header button.** Add a `Tooltip`-wrapped button next to Shortcuts
  (the `?` button from THI-69). Icon: `name="agent"` won't fit semantically;
  add a new `IconName = "docs"` (book glyph) to `Icon.tsx`. Default
  shortcut: none (the Docs modal is referenced infrequently; assign `g d`
  later if needed).
* **Tour step 4 (existing — see THI-96).** Append a "More in Docs"
  text-link below the existing tour content; clicking it dismisses the
  tour and opens the Docs modal.

### State

Add one boolean to `App.tsx` next to the existing modal toggles:

```ts
const [showDocs, setShowDocs] = useState(false);
```

Pass `onOpenDocs={() => setShowDocs(true)}` into `Header.tsx`. Render the
modal at the App level alongside `SettingsModal`.

### `DocsModal` component

```tsx
// frontend/src/components/DocsModal.tsx
interface Props { onClose: () => void; }

export function DocsModal({ onClose }: Props) {
  const [tab, setTab] = useState<DocsTab>("header");
  return (
    <Modal onClose={onClose} title="Documentation">
      <nav className="docs-tabs">
        <button className={tab === "header" ? "is-active" : ""}
                onClick={() => setTab("header")}>Session header</button>
        <button className={tab === "agent" ? "is-active" : ""}
                onClick={() => setTab("agent")}>Agent tile</button>
        <button className={tab === "shell" ? "is-active" : ""}
                onClick={() => setTab("shell")}>Shell tile</button>
      </nav>
      <div className="docs-body">
        {tab === "header" && <HeaderDiagram />}
        {tab === "agent"  && <AgentDiagram />}
        {tab === "shell"  && <ShellDiagram />}
      </div>
    </Modal>
  );
}
```

Each diagram component is a React component wrapping an inline SVG with
callout `<text>` and `<line>` arrows. They live in
`frontend/src/components/docs/` so the directory neatly contains all
three.

### SVG diagrams

Each diagram is hand-authored as a React inline SVG (no external `.svg`
file) so callout text can reuse CSS vars and theme colors. Template:

```tsx
export function AgentDiagram() {
  return (
    <svg viewBox="0 0 720 540" xmlns="http://www.w3.org/2000/svg">
      {/* The card itself — rendered as a slightly stylized illustration,
          not a real WindowCard, so the diagram doesn't drift when card
          internals change. */}
      <g className="diagram-card">
        <rect x="160" y="80" width="280" height="380" rx="10" />
        {/* …chip-row, recap line, pending block, foot row… */}
      </g>

      {/* Callouts — line + label, drawn outside the card to point at
          specific anchor coords. */}
      <CalloutLine from={[440, 110]} to={[560, 100]} />
      <text x="565" y="104">Status pill — see Status Legend</text>

      <CalloutLine from={[440, 165]} to={[560, 175]} />
      <text x="565" y="179">Branch + PR chip; CI dot color</text>

      {/* …~8 callouts total… */}
    </svg>
  );
}
```

A small `CalloutLine` helper renders a thin line with an arrowhead. Lives
in `components/docs/CalloutLine.tsx`. Keeps the diagram SVGs themselves
focused on geometry.

### Content per diagram

**Session header diagram** — callouts for:
* Session name (rename on click)
* Drag handle (drag-to-reorder, THI-115)
* +claude quick-create button (THI-115)
* +shell quick-create button (THI-115)
* Auto-rename ✨ (THI-67)

**Agent tile diagram** — callouts for:
* Kind glyph (Claude mark, THI-135)
* Window name (rename action in footer)
* Index `:N` (tmux window index)
* Status pill (link to Status Legend popover)
* Branch + PR chip (CI dot color meaning)
* Spinner chip (thinking state, with duration)
* Recap line (last assistant message)
* Pending block (amber — agent is waiting on you)
* Context % accent (left edge color band, THI-131)
* Footer actions: focus / rename / send / kill

**Shell tile diagram** — callouts for:
* Kind glyph (shell)
* Window name + index
* Status pill
* Branch chip (when in a git repo, THI-126)
* Preview lines (last captured output, density-controlled, THI-128)
* CPU / Memory meter (warn / danger tones)
* Footer actions: same as agent

### Styling

Diagram-specific CSS lives in `frontend/src/styles/docs.css`, imported
from `DocsModal.tsx`. Themed via CSS vars so light/dark/contrast all work
without per-theme overrides.

```css
.diagram-card rect { fill: var(--bg-elev); stroke: var(--hairline); }
.diagram-card .pill { fill: var(--accent-soft); }
.docs-modal text { fill: var(--text); font-size: 12px; font-family: var(--font-sans); }
.docs-modal .callout-line { stroke: var(--text-mute); stroke-dasharray: 2 3; }
```

// Header.tsx — between Shortcuts and Settings
<Tooltip content="Documentation">

New `docs` icon (`Icon.tsx`): a small book glyph, ~6 strokes.

### Tour step 4 link

`Tour.tsx` step 4 currently ends with "Press ⌘K anywhere to send commands."
Append a one-line footer:

```tsx
<button className="link" onClick={() => { dismissTour(); onOpenDocs?.(); }}>
  More in Docs →
</button>
```

`onOpenDocs` is a new optional prop on `Tour`, wired from `App.tsx`.

## Sequencing

The diagrams should reflect **final** UI. Author them after these
in-flight tickets ship — they touch surfaces called out in the diagrams:

* THI-67  — auto-rename ✨ (Agent tile + Session header)
* THI-128 — column width (Shell tile preview area context)
* THI-129 — Claude status placeholder (Agent tile shape)
* THI-130 — kind filters (no direct diagram impact, but UX touchstone)
* THI-131 — context-% accent (Agent tile left edge)
* THI-135 — Claude Code mark (Agent tile glyph)

Implementation order:

1. Land the modal shell + tab nav + Header button + `docs` icon + Tour
   link with **placeholder** diagrams (e.g. each tab shows the title and
   "diagram coming soon").
2. Author each diagram in its own PR once its referenced features are
   merged.
3. Final pass before v0.1 tag: verify every callout in every diagram
   matches shipped behavior.

## Testing

**Behavior:**

* Click Header → Docs button → modal opens; Esc closes; backdrop click
  closes.
* Tab switching (Session header / Agent tile / Shell tile) updates the
  body without remounting the modal.
* Tour step 4 "More in Docs" link dismisses the tour and opens the modal.
* Reload page after dismissing the tour with the link → tour stays
  dismissed (existing `switchboard:tour:v1:dismissed` localStorage key).
* Diagrams render at three viewport widths: 1440, 1280, 1024. Below 1024
  the modal can scroll horizontally — no responsive reflow required for
  v0.1.

**Visual:**

* Each diagram's callouts point at the correct anchor (verify by holding
  the diagram side-by-side with the real card screenshot).
* Themed correctly under dark / light (and contrast / phosphor, if the
  THI-134 audit found them already working).

## Open questions / future work

* **Keyboard shortcut.** None assigned for v0.1. `g d` would fit the
  Vim-style `g`-prefix style if we ever add one.
* **In-modal search.** Three diagrams is too few to justify; revisit if
  we add a 4th tab.
* **External docs site.** A future static site (e.g. on GitHub Pages —
  the deferred THI-132 covers part of this) could mirror these diagrams
  with deeper prose. Not required for v0.1.
* **Per-feature changelog.** A "What's new" tab is the obvious 4th tab
  candidate. Deferred.
